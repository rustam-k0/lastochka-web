# Ласточка Джами — веб-приложение

Мобильная демонстрационная версия продуктового магазина по шести скриншотам приложения. Седьмой скриншот сайта использован для фирменного знака и тёплого фона на больших экранах. Ширина приложения ограничена 440 px, на телефоне оно занимает весь экран.

## Запуск

Требуется Node.js 22.12+.

```sh
npm install
npm run dev
npm run build
npm run preview
npm test
```

`npm run test:e2e` проверяет работающий сервер на http://localhost:5173. Перед первым запуском установите Chromium: `npx playwright install chromium`. Если браузер уже установлен отдельно, задайте `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. `npm run screenshots` сохраняет снимки в `artifacts/`.

## Демоданные

Обычный вход: пустая корзина, фиктивный номер +7 000 000-00-00, ноль бонусов, нет адресов, заказов и избранного. Для воспроизведения референса откройте `/?demo` и нажмите **Загрузить демоданные**. Это явное действие заменяет текущие локальные данные. В корзине появятся четыре товара по одной штуке с итогом **1 037,40 ₽**. Сумма 887,40 ₽ из других скриншотов не подставляется.

## Маршруты и сценарии

- `/` — рекомендации, адрес, бонусы, QR-карта, акции.
- `/catalog` — 11 категорий в двух разделах.
- `/category/:id`, `/collection/:id`, `/product/:id` — списки и товар.
- `/search` — общий поиск по товару и категории, без различия е/ё и регистра.
- `/favorites`, `/profile`, `/notifications` — избранное, профиль и пустые уведомления.
- `/cart` — доставка/самовывоз, время, товары, комментарий, промокод, оплата, согласие, расчёт.
- `/orders`, `/orders/:id` — история и неизменяемый снимок тестового заказа.

Адреса (добавление, изменение, удаление, выбор), время, способы оплаты, профиль, локальный вход, бонусы, QR, штрихкод, документы, FAQ и поддержка открываются в панелях с управлением фокусом и закрытием по Escape. Очистка корзины требует подтверждения. «Поделиться» использует Web Share, затем буфер обмена, а при его недоступности показывает текст для ручного копирования. Выход оставляет данные на устройстве.

Промокод **ЛАСТОЧКА10** даёт одну скидку 10% на товары; округление происходит один раз в копейках. Доставка в демоверсии бесплатна. Заказ проверяет количество, наличие товара, адрес/пункт, интервал и согласие. Повторное нажатие во время оформления блокируется. После успеха корзина очищается, заказ сохраняет снимок цен, состава, получения, оплаты и комментария.

## Структура

- `src/app` — маршруты, layout, восстановление прокрутки, необязательный WebMCP.
- `src/pages` — основные и дополнительные экраны.
- `src/features` — persist-состояние Zustand, деньги, валидация, панели сценариев.
- `src/entities` — типы.
- `src/shared/ui` — диалог, шапка, товары, количества, уведомления.
- `src/services` — контракты каталога и оформления, mock-реализация.
- `src/data` — 26 товаров, категории, подборки, manifest изображений.
- `src/styles` — общие стили и токены; компоненты используют CSS Modules.
- `public/images` — локальные графические ресурсы без внешних сетевых зависимостей.

## Допущения и отличия

- Скрытые на референсах экраны выполнены в той же визуальной системе. Поля адреса, оплата, итог и предупреждение о деморежиме добавлены в корзину.
- SMS, оплата, касса, геокодинг, бонусные операции, отправка заказа, push и доставка не подключены. Поддержка и документы явно демонстрационные; контакты и реквизиты не выдуманы.
- QR представляет демонстрационную карту и не действует на кассе. Использован настоящий QR с демонстрационным текстом; его узор отличается от референса.
- Для штрихкода используется ручной ввод, пример `4600000000000`. Камера не нужна.
- Доступны три будущих дня, по три интервала; интервалы вычисляются при открытии и проверяются при оформлении. Смена режима, адреса или пункта сбрасывает время.
- Все товары штучные, остаток демонстрационный. Тип Product содержит `unit` и `quantityStep` для будущего расширения; текущая проверка принимает целые количества.
- Позиции прокрутки страниц запоминаются в рамках текущего сеанса. Маршруты поддерживают прямое открытие и браузерную навигацию.
- Нет системной строки iOS, персональный номер заменён, сумма согласована, нижний контент можно прокрутить выше закреплённых панелей. Это близкое воспроизведение, не заявление о pixel-perfect.

## Изображения

Использованы декоративные фрагменты предоставленных скриншотов: фотографии четырёх товаров корзины, предметные фрагменты категорий и рекомендаций, ласточка из избранного и фирменный знак из сайта. Интерфейс, подписи категорий, кнопки и заголовки — HTML, а не скриншоты экранов. Метод извлечения сохранён в `scripts/extract-assets.py`; его исходные пути относятся к вложениям этой задачи, но для запуска проекта оригиналы не нужны.

Поскольку отдельных исходных ассетов нет, часть фотографий обрезана и фон подобран приблизительно. Изображения хлебцев и сухарей временно используют фото хлеба; дополнительные демотовары используют общее фото соответствующей категории (в том числе мангал, салаты, пицца, молочные продукты и бытовая химия). Их следует заменить индивидуальными фотографиями через `src/data/manifest.ts`. Ласточка извлечена из референса, не сгенерирована заново. Тексты на товарных упаковках остаются частью фото.

## Состояние и реальные интеграции

`localStorage['lastochka-shop']`, версия схемы 1. Начальное состояние не перезаписывает сохранённое; demo preset запускается только после явного подтверждения. Локальное состояние принадлежит этому браузеру и не синхронизируется между устройствами.

Для интеграции замените `CatalogService` и `CheckoutService` в `src/services/shop.ts`. При смене активного адреса интерфейс повторно вызывает `availability`; mock возвращает тот же набор. При оформлении доступность и интервалы проверяются повторно. В реальном приложении UI должен получать ассортимент и цены асинхронно от сервера, а сервер обязан авторитетно проверять цены, остатки, скидки, итог и идемпотентность заказа. localStorage не является складской системой. Профиль, платежи и уведомления также требуют реальных провайдеров.

SPA-хостинг должен возвращать `index.html` для неизвестных путей. Статическая сборка лежит в `dist`; `.openai/hosting.json` содержит конфигурацию Sites.

## Проверка

- Тесты денежного расчёта, скидки, валидации заказа и поиска.
- Браузерный сценарий доставки и самовывоза, промокод, согласие, защита от повторного нажатия, снимок заказа, перезагрузка, избранное, адреса, гостевой профиль, диалог и восстановление фокуса.
- Проверка отсутствия горизонтальной прокрутки и загрузки изображений на 360, 390, 430 и 1280 px.
- Снимки шести основных экранов и успешного заказа в `artifacts/`; выполнено визуальное сравнение композиции с референсами.
- Необязательный read-only инструмент WebMCP `search_shop_products` регистрируется только при наличии `document.modelContext`. Нативная проверка WebMCP недоступна в текущем браузере; обычный поиск не зависит от этой возможности.
