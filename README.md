# Ласточка Джами — веб-приложение

Адаптивная демонстрационная версия продуктового магазина по шести скриншотам приложения. Седьмой скриншот сайта использован для фирменного знака и тёплого фона на больших экранах. На телефоне приложение занимает весь экран, на более широких окнах появляются боковые поля; максимальная ширина — 1280 px.

## Запуск

Требуется Node.js 22.13+ (рекомендуется 24 LTS). SQLite подключён через встроенный `node:sqlite`.

```sh
npm install
npm run dev
npm run build
npm start
npm test
```

`npm run dev` запускает интерфейс на http://localhost:5173 и API на http://127.0.0.1:3001. Первый запуск автоматически создаёт SQLite и импортирует каталог. `npm run build && npm start` запускает собранное приложение вместе с API на порту 3001. Для разработки только интерфейса есть `npm run dev:client` (API должен быть запущен отдельно). `npm run preview` также требует работающий API.

`npm run test:e2e` сам собирает приложение и запускает временный сервер с отдельной SQLite; пользовательская база не затрагивается. Перед первым запуском установите Chromium: `npx playwright install chromium`. Если браузер уже установлен отдельно, задайте `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. Снимки сохраняются в `test-results/e2e/`.

`npm run test:responsive` проверяет восемь основных ширин, промежуточные размеры, короткие окна, диалоги, прокрутку над закреплёнными панелями и оформление заказа. Проверка 200% использует настоящий масштаб Chromium через временное локальное расширение (нужен установленный Playwright Chromium). Снимки и результаты сохраняются в `test-results/responsive/`. Все сценарии работают в изолированных браузерных профилях и не затрагивают пользовательские данные. Сценарий также запускается с отдельной временной SQLite; только для этой проверки остатки увеличены до 1000, чтобы хватило на все размеры. Для внешнего сервера можно вызвать `TEST_ORIGIN=… node scripts/e2e.mjs` напрямую.

## Адаптивная компоновка

Мобильное оформление сохранено. Сетки подборок и товаров добавляют колонки с минимальной шириной карточки 180 px, категории — 132 px. Нижняя навигация, поиск, корзина и панель оформления ограничены шириной 640 px. Под закреплёнными элементами оставлен запас прокрутки, включая пустое избранное и короткие окна.

Карточка товара использует две колонки от 760 px, корзина — от 960 px; порядок элементов в разметке остаётся прежним. Профиль и подробности заказа ограничены 720 px, диалоги — 560 px. На телефоне диалоги сохраняют нижнее расположение, на широком экране центрируются и прокручиваются в пределах доступной высоты. Шрифты, цвета, изображения, маршруты и логика состояния не заменялись.

## Демоданные

Обычный вход: пустая корзина, фиктивный номер +7 000 000-00-00, ноль бонусов, нет адресов, заказов и избранного. Для воспроизведения референса откройте `/?demo` и нажмите **Загрузить демоданные**. Это явное действие заменяет текущие локальные данные. В корзине появятся четыре товара по одной штуке с итогом **1 037,40 ₽**. Сумма 887,40 ₽ из других скриншотов не подставляется. Режим не удаляет серверные заказы и не восстанавливает остатки: каждый успешно оформленный тестовый заказ уменьшает их в базе. При перезагрузке серверная история появится снова.

## Маршруты и сценарии

- `/` — рекомендации, адрес, бонусы, QR-карта, акции.
- `/catalog` — 11 категорий в двух разделах.
- `/category/:id`, `/collection/:id`, `/product/:id` — списки и товар.
- `/search` — общий поиск по товару и категории, без различия е/ё и регистра.
- `/favorites`, `/profile`, `/notifications` — избранное, профиль и пустые уведомления.
- `/cart` — доставка/самовывоз, время, товары, комментарий, промокод, оплата, согласие, расчёт.
- `/orders`, `/orders/:id` — история и неизменяемый снимок тестового заказа.

Адреса (добавление, изменение, удаление, выбор), время, способы оплаты, профиль, локальный вход, бонусы, QR, штрихкод, документы, FAQ и поддержка открываются в панелях с управлением фокусом и закрытием по Escape. Очистка корзины требует подтверждения. «Поделиться» использует Web Share, затем буфер обмена, а при его недоступности показывает текст для ручного копирования. Выход оставляет данные на устройстве.

Промокод **ЛАСТОЧКА10** даёт одну скидку 10% на товары; округление происходит один раз в копейках. Доставка в демоверсии бесплатна. Заказ проверяет количество, наличие товара, адрес/пункт, интервал и согласие. Повторное нажатие во время оформления блокируется. После успеха корзина очищается, заказ сохраняет снимок цен, состава, получения, оплаты и комментария.

## Структура

- `src/app` — маршруты, layout, восстановление прокрутки, необязательный WebMCP.
- `src/pages` — основные и дополнительные экраны.
- `src/features` — persist-состояние Zustand, деньги, валидация, панели сценариев.
- `src/entities` — типы.
- `src/shared/ui` — диалог, шапка, товары, количества, уведомления.
- `src/services` — HTTP-клиент каталога и оформления, реактивный кэш каталога.
- `server` — Express API, SQLite, миграции, оформление и резервное копирование.
- `src/data` — начальные данные 26 товаров и категорий; конфигурация подборок, промокода, пункта самовывоза и изображений.
- `src/styles` — общие стили и токены; компоненты используют CSS Modules.
- `public/images` — локальные графические ресурсы без внешних сетевых зависимостей.

## Допущения и отличия

- Скрытые на референсах экраны выполнены в той же визуальной системе. Поля адреса, оплата, итог и предупреждение о деморежиме добавлены в корзину.
- SMS, оплата, касса, геокодинг, бонусные операции, отправка заказа, push и доставка не подключены. Поддержка и документы явно демонстрационные; контакты и реквизиты не выдуманы.
- QR представляет демонстрационную карту и не действует на кассе. Использован настоящий QR с демонстрационным текстом; его узор отличается от референса.
- Для штрихкода используется ручной ввод, пример `4600000000000`. Камера не нужна.
- Доступны три будущих дня, по три интервала; интервалы вычисляются при открытии и проверяются при оформлении. Смена режима, адреса или пункта сбрасывает время.
- Все товары штучные, остаток демонстрационный. Тип Product содержит `unit` и `quantityStep` для будущего расширения; текущая проверка принимает целые количества.
- Позиции прокрутки страниц запоминаются в рамках текущего сеанса. Маршруты поддерживают прямое открытие и браузерную навигацию.
- Нет системной строки iOS, персональный номер заменён, сумма согласована, нижний контент можно прокрутить выше закреплённых панелей. Это близкое воспроизведение, не заявление о pixel-perfect.

## Изображения

Использованы декоративные фрагменты предоставленных скриншотов: фотографии четырёх товаров корзины, предметные фрагменты категорий и рекомендаций, ласточка из избранного и фирменный знак из сайта. Интерфейс, подписи категорий, кнопки и заголовки — HTML, а не скриншоты экранов. Метод извлечения сохранён в `scripts/extract-assets.py`; его исходные пути относятся к вложениям этой задачи, но для запуска проекта оригиналы не нужны.

Поскольку отдельных исходных ассетов нет, часть фотографий обрезана и фон подобран приблизительно. Изображения хлебцев и сухарей временно используют фото хлеба; дополнительные демотовары используют общее фото соответствующей категории (в том числе мангал, салаты, пицца, молочные продукты и бытовая химия). Их следует заменить индивидуальными фотографиями через `src/data/manifest.ts`. Ласточка извлечена из референса, не сгенерирована заново. Тексты на товарных упаковках остаются частью фото.

## База данных и API

По умолчанию база — `data/lastochka.sqlite`. Путь задаётся через `DATABASE_PATH`. Миграция `server/migrations/001_initial.sql` создаёт четыре таблицы:

| Таблица       | Поля                                                                                                                                                                                                                                                                  |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `categories`  | `id`, `name`, `group_name`, `image_url`, `color`, `sort_order`, `is_visible`                                                                                                                                                                                          |
| `products`    | `id`, `category_id`, `sku`, `name`, `description`, `image_url`, `price`, `unit`, `stock`, `quantity_step`, `is_active`, `sort_order`                                                                                                                                  |
| `orders`      | `id`, `owner_hash`, `idempotency_key`, `request_hash`, `created_at`, `status`, `customer_name`, `customer_phone`, `fulfillment_mode`, `pickup_id`, `destination`, `slot`, `comment`, `payment_method`, `subtotal`, `discount`, `delivery_cost`, `total`, `consent_at` |
| `order_items` | `id`, `order_id`, `product_id`, `product_name`, `sku`, `image_url`, `unit`, `unit_price`, `quantity`, `product_snapshot`                                                                                                                                              |

Цены — целые копейки. Включены внешние ключи, ограничения, индексы и WAL. `PRAGMA user_version` хранит версию миграции. Начальные данные импортируются только при создании базы; перезапуск не перезаписывает цены и остатки. Четыре служебные категории для уже существующих товаров скрыты в каталоге, поэтому набор видимых разделов не изменился. Фото остаются файлами, в таблицах — пути к ним.

| Метод                          | Назначение                                                                |
| ------------------------------ | ------------------------------------------------------------------------- |
| `GET /api/health`              | Проверка доступности сервера и базы                                       |
| `GET /api/catalog`             | Товары и категории из базы, подборки из конфигурации                      |
| `GET /api/slots?mode=delivery` | Доступные интервалы (также `pickup`), часовой пояс магазина Europe/Moscow |
| `GET /api/orders`              | История текущей гостевой сессии; создаёт cookie при первом посещении      |
| `GET /api/orders/:id`          | Заказ только текущей сессии                                               |
| `POST /api/orders`             | Валидация, расчёт и атомарное сохранение заказа                           |

Сервер принимает идентификаторы товаров, количества, получение, комментарий, контактные данные, способ оплаты, промокод, согласие, ожидаемый итог и уникальный ключ запроса. Итог пересчитывается по базе; изменение цены требует повторного подтверждения пользователем. Сервер сохраняет снимки товара и адреса и списывает остатки в одной транзакции. Ошибка откатывает все записи. Одинаковый повтор запроса возвращает прежний заказ, другой запрос с тем же ключом отклоняется. Вкладка хранит ключ незавершённой отправки в sessionStorage для повторной попытки после потери ответа.

Доступ к истории привязан к случайной HttpOnly/SameSite cookie; в базе хранится её хеш. Номера заказов не дают доступа к чужим данным. В HTTPS cookie получает флаг Secure. Это гостевая сессия, а не полноценная авторизация: демонстрационный вход по телефону не связывает устройства. Утрата cookie означает утрату доступа к серверной истории из интерфейса.

Корзина, избранное, адреса и демонстрационный профиль остаются в `localStorage['lastochka-shop']`, версия схемы 1. Серверные заказы кэшируются там же и обновляются при загрузке приложения; старые локальные заказы сохраняются и не загружаются на сервер автоматически. Начальное состояние не перезаписывает сохранённое. При недоступности API показана ошибка с повторной попыткой, фиктивного успешного оформления нет.

Оплата, SMS, передача заказа магазину, уведомления и панель администратора не подключены. Все заказы остаются тестовыми. Адрес доставки пока проверяется только на заполнение, геокодинга и зон доставки нет. Интерфейс редактирования каталога не добавлен; изменения в SQLite видны после обновления страницы.

## Размещение и резервные копии

Нужен один Node.js-процесс с постоянным локальным диском. Укажите `DATABASE_PATH=/постоянный-диск/lastochka.sqlite`, `HOST=0.0.0.0`, `PORT` и `PUBLIC_ORIGIN=https://ваш-домен`. `PUBLIC_ORIGIN` должен совпадать с адресом сайта; используйте HTTPS через обратный прокси. Сервер раздаёт `dist` и обрабатывает маршруты SPA. Старый `.openai/hosting.json` описывает только статическую сборку и не разворачивает API/SQLite.

`npm run db:backup` делает согласованную копию работающей базы в `backups/`. Можно задать путь: `npm run db:backup -- /путь/копия.sqlite`. Команда не перезаписывает существующий файл. Базы, WAL-файлы и резервные копии исключены из Git. Храните резервные копии также вне диска сервера; автоматическое расписание не настроено.

Для восстановления остановите сервер, сохраните текущую базу и её `-wal`/`-shm` отдельно и замените базу резервной копией. Рядом с восстановленным файлом не должно быть старых `-wal`/`-shm`; затем запустите сервер. Не копируйте только основной файл работающей базы вручную: последние записи могут находиться в WAL.

## Проверка

- Тесты денежного расчёта, скидки, валидации заказа и поиска; серверные тесты SQLite, миграции, остатков, снимков, повторов, изоляции сессий, перезапуска и отката транзакции.
- Браузерный сценарий доставки и самовывоза, промокод, согласие, защита от повторного нажатия, снимок заказа, перезагрузка, избранное, адреса, гостевой профиль, диалог и восстановление фокуса.
- Проверка компоновки на 360, 390, 430, 768, 1024, 1280, 1440 и 1920 CSS px: ширина контейнера, число колонок, отсутствие выхода элементов за экран, доступность последнего элемента над закреплёнными панелями, оформление и сохранение заказа на каждой ширине.
- Промежуточные размеры около точек перестроения, 320 px, альбомное окно 844 × 390 и сокращённая область 390 × 300 для имитации экранной клавиатуры. Реальный браузерный масштаб 200% проверяется в окнах шириной 768–1920 px, включая оформление заказа; это браузерная проверка, а не тест физических телефонов.
- Снимки шести основных экранов и успешного заказа в `test-results/e2e/`; выполнено визуальное сравнение композиции с референсами.
- Необязательный read-only инструмент WebMCP `search_shop_products` регистрируется только при наличии `document.modelContext`. Нативная проверка WebMCP недоступна в текущем браузере; обычный поиск не зависит от этой возможности.
